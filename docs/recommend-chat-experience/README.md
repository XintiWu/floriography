# 情境推薦：花語顧問聊天體驗（V2）

本文件說明 `/recommend` 頁面目前的「花語顧問聊天體驗」功能設計、資料流與可調參數，供後續維護與迭代使用。

## 1. 功能目標

- 讓使用者從輸入故事到拿到三張推薦卡，感受像在對話而非表單提交。
- 降低等待焦慮：分析過程要看得見進度。
- 提高可發現性：推薦完成後自動帶到卡片區。
- 保留上下文：使用者下滑看卡片時仍可快速回看顧問完整回覆。

## 2. 主要互動流程

1. 使用者輸入故事後，按下 `AI 分析並推薦`。
2. 前端先呼叫 `POST /api/parse-story` 解析欄位。
3. 解析欄位以「逐格填入」方式更新右側表單（約 240ms/格）。
4. 前端再呼叫 `POST /api/recommend`（`mode: refine`）取得顧問回覆與推薦卡。
5. 取得推薦後：
   - 聊天室顯示完整顧問回覆。
   - 顯示右下角浮動小氣泡（完整顧問回覆，可捲動）。
   - 自動平滑捲到三張卡片區。
6. 點擊浮動小氣泡可快速捲回 `STORY INPUT` 區塊（含聊天室）。

## 3. 畫面與狀態說明

### 3.1 聊天室（左欄）

- 預設即顯示，不需先分析，避免左欄空白。
- 顯示初始引導訊息。
- 使用者送出故事後，聊天室追加「使用者泡泡」與「顧問泡泡」。

### 3.2 進度顯示

- 進度卡使用三點動畫，不顯示「對方正在輸入」文案。
- 階段文案：
  - `正在解析您的故事`
  - `正在整理需求欄位`
  - `正在為您推薦卡片`

### 3.3 浮動小氣泡（右下）

- 固定右下角，窄版寬度，盡量避免遮擋第三張卡片。
- 內容顯示完整顧問回覆，超長時內部捲動。
- 點擊後捲回上方 `STORY INPUT`。

## 4. 標籤回填策略（情緒/花語）

右欄標籤來源有兩層：

1. `parse-story` / `recommend` 回傳欄位中的 `mood`、`flowerMeaning`。
2. 若上述無法對到既有 tag，啟用故事關鍵字 fallback：
   - 以 regex 對故事做關鍵字比對。
   - 對應到既有 `MOOD_ATMOSPHERE_TAGS` 與 `FLOWER_MEANING_TAGS`。

目的：避免「分析成功但 chips 沒亮」的體感錯誤。

## 5. 目前關鍵檔案

- `src/components/recommend/RecommendForm.tsx`
  - 主流程控制（兩階段 API、逐格填入、聊天室、浮動小氣泡、自動捲動）。
- `src/components/recommend/RecommendLoadingProgress.tsx`
  - 三點動畫與狀態訊息。
- `src/lib/recommendOllama.ts`
  - 顧問語氣規範、回覆收尾句、fallback 文案。

## 6. 重要設計決策

- 花語欄位採「只允許既有 # tags」，不提供自由輸入欄位。
- 顧問語氣不使用「呀／啦」結尾助詞。
- 推薦完成後自動下拉，但提供浮動氣泡快速回看顧問全文。

## 7. 後續建議

- 可把浮動小氣泡改為「可展開/收合」以進一步減少遮擋。
- 可依 viewport 動態調整氣泡寬高（例如超寬螢幕放寬，窄螢幕更窄）。
- 若未來要更即時，可改為 SSE 串流逐段顯示顧問回覆與推薦狀態。
